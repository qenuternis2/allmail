# Улучшения отпечатка v0.1.4

В пользовательском отчёте браузер использовал Africa/Nairobi (+03:00), а IP был
геолокирован в Europe/Berlin (+02:00 на дату отчёта). Совпадение основной версии
154 скрывало предупреждение о Chrome-подобном UA и брендах Edge/WebView2.
ID отпечатка включал RTT, скорость сети и размеры окна и поэтому не был устойчивым.
Замаскированные адреса не позволяют установить утечку IPv4/IPv6 или прямой выход.

## Изменения

- Часовой пояс IANA задаётся отдельно для каждого профиля. Пустое поле — системный.
  Применяется нативным `Emulation.setTimezoneOverride` до целевой навигации
  основного окна, дочерних окон и диагностики. Функции Date/Intl не подменяются.
  Основное окно и диагностика проверяют Intl и зимнее/летнее смещение Date
  в собственном about:blank после NavigationCompleted. Ошибка применения
  блокирует открытие основного окна; дочерний контроллер остаётся ненавигированным
  до NewWindowRequested. Общая проверка workers и OOPIF не выполнена.
- SQLite v2 → v3: nullable BrowserTimeZoneId, резервная копия до миграции.
  Старые профили остаются с системным поясом. Настройка переносится импортом/экспортом;
  старые JSON v1 без этого поля принимаются. Данные браузера, разрешения,
  снимки ревизий и даты напоминаний сохраняются. Изменение требует перезапуска.
- Прокси-профили блокируются при внешних аргументах WebView2 из переменной среды
  или политики реестра, которые могут изменить выбранный маршрут. Ранее это
  проверялось только при экспериментальном ограничении UDP WebRTC.
- ID среды v2 исключает RTT/скорость, размеры окна, доступную область экрана
  и хранилище; отдельный stateFingerprintId описывает экран и соединение сейчас.
  Версия, аппаратные признаки, DPI, язык и часовой пояс могут менять ID среды.
  ID не измеряет уникальность и несопоставим с ID из предыдущего сборщика.
- Проверки UA сравнивают Chromium, бренд, платформу и HTTP/JavaScript представления.
  WebView2 показывается явно. Несовпадение страны IP и языка — информация,
  а не доказательство утечки. Уточнены ограничения permissions.query и шрифтов.
- Маршруты прокси, DNS, сеть WebRTC и полное покрытие контекстов явно NotPerformed.

## Проверки и ограничения

222 теста ядра и 18 JavaScript-тестов: валидация, сезонные смещения Berlin,
миграция v2/v1 с сохранением данных и резервной копией, перенос настройки,
перезапуск только нужного профиля, устойчивость ID при изменении RTT/окна,
расхождения UA/Client Hints/HTTP. Core и Experimental компилируются отдельно.
Автоматические тесты не проверяют выполнение CDP внутри Windows WebView2.

Для исходного немецкого выхода задайте Europe/Berlin и User-Agent «По умолчанию»,
перезапустите профиль и сохраните новый отчёт. Проверьте смену навигации и дочерние
окна, одновременно откройте профиль с другим поясом и убедитесь в изоляции.
На контролируемом стенде сравните Date/Intl в главном документе, same-origin,
cross-origin/OOPIF, dedicated/shared/service workers и после смены процесса.
Проверьте IPv4/IPv6, DNS и отказ прокси сетевым захватом по WEBRTC_FIX_REPORT.md.

Полная анонимность, несвязываемость профилей и отсутствие IP-утечек не заявляются.
Canvas/Audio/WebGL/WebGPU и шрифты остаются доступными. Блокировка WebRTC сохранена.
Для возврата к приложению со схемой v2 потребуется предмиграционная резервная копия
метаданных; папка данных WebView2 этой миграцией не изменяется.

# Тестовые профили и ограничение графики v0.1.5

В новом пользовательском отчёте от 03.10.2026 часовой пояс Europe/Berlin и смещение
+02:00 совпадают с IP, штатный UA содержит Edg и согласован с Client Hints.
Это наблюдение одной диагностической страницы. RTX 4060 по-прежнему доступна через
WebGL и WebGPU; CPU, память, Canvas, Audio и шрифты остаются видимыми.
IPv4 скрыт пользователем, IPv6 пуст: вывод о маршруте по этому файлу невозможен.

## Реализовано

- Отдельный тип Test и кнопка «Тестовый профиль…»: HTTP/HTTPS URL, порты, локальные
  стенды, переходы между сайтами и дочерние окна внутри профиля. Для каждого нового
  профиля создаётся свежий UUID и своя папка браузера; данные почтовых профилей
  не копируются. Почтовая политика разрешённых origin не расширяется.
- Новый профиль остаётся закрытым до выбора сети и настроек. Изменение URL
  перезапускает только этот профиль. Профиль Test без URL, например после импорта
  экспорта без адресов, заблокирован и не переключается на почту.
- Экспериментальное ограничение графики, включаемое отдельно:
  `--disable-webgl --disable-features=WebGPU,WebGPUService`. Два имени feature
  учитывают различия Chromium Runtime. Никакие модели GPU не выдумываются,
  Canvas 2D/Audio/CPU/память/шрифты не подменяются. Опция может нарушить 3D и карты.
  Полная строка сохраняет прокси и флаг WebRTC; внешние аргументы блокируют открытие.
  В owned about:blank до открытия основной страницы проверяется отсутствие
  WebGL-контекста у Canvas и OffscreenCanvas. WebGPU там не считается проверенным:
  ему требуется secure context. Дочерние контроллеры остаются ненавигированными.
- Отчёт v3 наблюдает главный документ и локальный dedicated worker: timezone,
  UTC offset, CPU/память, WebGL и выдачу WebGPU-адаптера. Статусы графики относятся
  только к наблюдаемым контекстам: Pass/Fail/NotPerformed/NotApplicable. Ошибка
  или таймаут не превращается в Pass. Worker и Blob URL освобождаются.
  Наблюдение не доказывает действие флага: API могли отсутствовать и без него.
- IPv4/IPv6 ответ валидируется отдельно; пустой ответ, таймаут и ошибка не
  подтверждают отсутствие IPv6 или прямого трафика. Проверки маршрутов, DNS,
  сети WebRTC и всех контекстов остаются NotPerformed.
- Сохранённый fingerprint JSON по умолчанию скрывает известные поля IP/hostname,
  address в сетевых наблюдениях и forwarded/IP HTTP-заголовки. Живой локальный
  отчёт не меняется. Галочка позволяет явный экспорт адресов. Частичный отчёт
  ошибки также маскируется; некорректный JSON не сохраняется как сырой fallback.
- Экспорт настроек по умолчанию исключает полный тестовый URL. Включение адресов
  прокси и тестовых URL выбирается отдельно. В общий отчёт диагностики URL не попадает.
- SQLite v3 → v4 с предмиграционной резервной копией. Существующие профили остаются
  Mail, графика RuntimeDefault. Данные браузера, разрешения, снимки и timezone сохраняются.

## Проверки

246 тестов ядра и 22 JavaScript-теста: политики навигации и запрещённых схем,
изоляция поколений и папок, URL/настройки/импорт без адресов, сохранение прокси и
WebRTC в аргументах, миграции v1/v2/v3, экспорт IP, WebGL readback, обработка IPv6,
исходы наблюдения графики и освобождение worker. Core и Experimental компилируются.
VM-тесты не проверяют выполнение browser flags и GUI в Windows WebView2.

На Windows создайте Test-профиль, настройте его до открытия сайта, проверьте
переходы на другой HTTP/HTTPS origin и child window. Измените URL и перезапустите;
убедитесь, что почтовый профиль сохранил свою политику и сессию. Сравните отпечаток
с включённой и выключенной графикой в отдельном тестовом профиле. Проверьте main,
same-origin/cross-origin/OOPIF, dedicated/shared/service workers, смену процесса
и одновременные профили с разными политиками. Полное покрытие не проверено.

Для возврата к приложению со схемой v3 потребуется резервная копия метаданных.

# Исправление графического режима 0.1.6

Диагностика пользователя от 2026-10-03 показывает WebView2 Runtime 154.0.4258.53,
проверку WebRTC Verified и отказ открытия Test-профиля при отключении графики.
После завершения процесса причина заменялась строкой «Восстановлено после ошибки запуска».

`--disable-webgl` задаёт настройки документа. Chromium OffscreenCanvas возвращает
`true` из `IsWebGL1Enabled`/`IsWebGL2Enabled` и эти настройки не учитывает:
[исходник OffscreenCanvas](https://github.com/chromium/chromium/blob/main/third_party/blink/renderer/core/offscreencanvas/offscreen_canvas.h).
Поэтому штатная проверка OffscreenCanvas могла обоснованно блокировать открытие.

Добавлены `--disable-gpu --disable-software-rasterizer`: запрещаются GPU-доступ
и программный 3D-резерв. Старые `--disable-webgl` и отключение WebGPU features
сохранены вместе с аргументами прокси/WebRTC. JavaScript API не подменяются.
Отключаются также ускорение интерфейса и видео; производительность может снизиться.
Canvas 2D остаётся доступным на CPU, Audio и шрифты не меняются.

Проверка возвращает отдельные результаты Canvas WebGL/experimental-webgl/WebGL2
и OffscreenCanvas WebGL/WebGL2. Живой контекст указывается в ошибке; null, ошибка
скрипта, отсутствующие или неверно типизированные результаты не считаются успешной
блокировкой. Открытие до целевого URL по-прежнему блокируется при отказе проверки.
Причина ошибки и версия Runtime сохраняются после восстановления до нового запуска.

260 тестов .NET и 22 JavaScript-теста прошли локально. Добавлен обязательный
[Windows WebView2 стенд](tests/ProtonProfiles.WebView2.Smoke/README.md) в CI и релиз:
свежие UDF, старые/новые флаги, основной и второй контроллер одной среды,
проверка WebRTC, локальный HTTPS, WebGL/WebGPU в документе и dedicated worker,
положительная проверка пикселя Canvas 2D. Лог включается в ZIP.
Windows CI на Runtime 153.0.4234.48 воспроизвёл старую ошибку: Canvas WebGL/WebGL2
недоступны, OffscreenCanvas WebGL/WebGL2 доступны и в документе, и в worker.
С новыми флагами начальная проверка Verified в обоих контроллерах; в локальном
HTTPS документе и worker WebGL/WebGL2 недоступны, WebGPU адаптер не выдаётся,
пиксель Canvas 2D корректен. Это проверка среды CI; Runtime пользователя
154.0.4258.53 отдельно не запускался.
Этот стенд не доказывает полное покрытие всех контекстов или отсутствие IP-утечек.

# Canvas readback 0.1.7

Пользователь подтвердил, что наблюдаемый IPv6 принадлежит прокси. Это принимается
как его локальное наблюдение; автоматические проверки маршрутов остаются NotPerformed.
Отчёт 2026-10-03 14:22 подтверждает отключение WebGL/WebGPU в документе и dedicated
worker на Runtime 154.0.4258.53; Canvas/Audio, CPU, память, экран и шрифты доступны.
В текущем Chromium deviceMemory 32 — штатный верхний предел на desktop,
а не самостоятельный признак неисправности или подмены.

Добавлено значение GraphicsPolicy `BlockWebGlWebGpuAndCanvasReadbackExperimental`.
Пользователь выбирает его отдельно в настройках. Существующий режим WebGL/WebGPU
и данные профилей сохраняются; SQLite остаётся v4. Импорт/экспорт и JSON Schema
поддерживают новый enum; старый бинарник этот режим не поддерживает.

К прежним аргументам добавляется `--disable-reading-from-canvas`.
Это нативная настройка Chromium: OriginClean для HTML Canvas становится false;
OffscreenCanvas 2D получает её из Settings/WorkerSettings. JavaScript API и
результаты рисования не подменяются. getImageData, toDataURL, toBlob и
OffscreenCanvas.convertToBlob должны выдавать SecurityError. Команды рисования
остаются доступны, однако экспорт изображений, редакторы и проверки сайтов могут
сломаться. Font measureText, Audio, CPU/память, экран/DPI и Client Hints не скрыты.

Один общий сборщик наблюдений используется в owned blank перед целевым URL,
диагностике и Windows стенде. Через Runtime.evaluate/awaitPromise перед открытием
проверяются все пять путей чтения в документе, включая OffscreenCanvas.
SecurityError означает Blocked; другой сбой, таймаут, null и отсутствующие поля —
Unavailable. Любое Readable блокирует старт. Диагностика v4 проверяет документ
и dedicated worker, сохраняет команды рисования и продолжает Audio/Math при
запрете Canvas-хэша. Значение хэша — «чтение заблокировано»; ID версии 2 по-прежнему
не является доказательством уникальности или невозможности связывания профилей.

Локально прошли 275 тестов .NET и 25 JavaScript-тестов. Windows стенд расширен:
старые режимы дают положительные контроли чтения, новый — запрет всех пяти
экспортов в двух контроллерах и dedicated worker; проверяется awaited стартовый
скрипт и настоящая bundled fingerprint.html с локальными HTTP-заглушками.
Проверки всех origin/OOPIF/shared/service workers и реальных сетевых маршрутов
этим не подтверждаются. Ускорение GPU по-прежнему отключено в обоих режимах.

Windows CI на WebView2 153.0.4234.48 прошёл: стартовый CDP readback Verified
в обоих контроллерах, все пять экспортов Blocked в документе, два offscreen
экспорта Blocked в dedicated worker, команды рисования доступны. Настоящая
fingerprint.html дала Canvas/graphics Pass в обоих контекстах, отчёт v4 завершён,
Audio/Math сохранены; внешние HTTP-ответы в этом тесте заданы локально.

# Web Audio в документах 0.1.8

Пользовательский отчёт 03.10.2026 15:17 (Runtime 154.0.4258.53) подтверждает
WebGL/WebGPU и Canvas Pass в документе и dedicated worker. Europe/Riga и +03:00
согласованы в наблюдаемых контекстах. Прежний Audio-хэш сохраняется:
124.0434777670 / c40eda39b983616b. IPv6 NotObserved не доказывает отсутствия IPv6
или утечки; ранее пользователь подтвердил принадлежность адреса прокси.

Новый opt-in GraphicsPolicy `BlockGraphicsCanvasAndWebAudioExperimental`
сохраняет нативные GPU/Canvas аргументы и добавляет document-created guard для
AudioContext, OfflineAudioContext и двух webkit-псевдонимов. Это JavaScript-ограничение
конструкторов в документах, не нативное отключение аудиодвижка. Глобальные и имеющиеся
унаследованные точки входа заменяются immutable undefined без сохранения конструкторов
или функции восстановления. Стандартные Audio/HTMLAudioElement/HTMLVideoElement,
WebCodecs и Media APIs этим скриптом не отключаются. Все способы аудиоотпечатка
и полное покрытие контекстов не заявляются; отсутствие API само по себе заметно сайту.

Регистрация выполняется независимо от настройки WebRTC во всех контроллерах профиля,
включая дочерние окна и частную диагностику. Перед целевым URL выполняется owned blank
и readback дескрипторов. Ошибка регистрации/проверки блокирует старт. Дочерний контроллер
регистрирует защиту до передачи NewWindowRequested и остаётся ненавигированным.
Поздняя проверка доступных документов/frames закрывает профиль только при явном false
в текущем поколении и документе. Null, исключение, уничтоженный frame, навигация во время
await и устаревшее поколение не становятся Violation. Поздняя проверка не предотвращает
раннюю активность ретроспективно. Счётчики без URL сохраняются после закрытия/сбоя и
сбрасываются при новом запуске. Общий диагностический coverage остаётся NotPerformed.

Диагностика v5 использует общий наблюдатель: подтверждённый guard даёт «Web Audio
заблокирован» вместо хэша. Естественное отсутствие Window API в dedicated worker —
NotApplicable, а не Pass. Неполные данные — NotPerformed. Canvas/Math и прочие разделы
продолжают собираться. SQLite v4 сохраняется, enum поддержан импортом/экспортом и
JSON Schema. Старые бинарники новый режим не поддерживают.

Локально прошли 284 теста .NET и 31 JavaScript-тест. Обе сборки и Windows harness
компилируются без предупреждений. Windows harness проверяет положительное offline
рендерирование в прежних режимах, блокировку в новом, основной и второй контроллер,
загруженные same-origin/srcdoc/cross-origin iframe и реальную bundled диагностику.
Начальный пустой iframe проверяется отдельно немедленным доступом к конструктору;
покрытие не выводится из загруженных iframe. HTML Audio API проверяется на наличие, физическое воспроизведение не проверяется.
CPU/RAM, экран/DPI, шрифты, Math и WebView2 Client Hints этим режимом не скрываются.

Windows CI на WebView2 153.0.4234.48 прошёл: baseline OfflineAudioContext реально
рендерит буфер, новый режим блокирует конструкторы в основном/втором контроллере
и загруженных same-origin/srcdoc/cross-origin фреймах. В немедленно созданном пустом
iframe конструктор также недоступен; baseline допускает его создание. Реальная
fingerprint.html выдаёт v5, main Web Audio Pass и worker NotApplicable, Canvas/graphics
Pass в обоих контекстах, Audio-хэш заблокирован, Math сохранён. Сочетание с WebRTC Allow также прошло:
конструктор RTCPeerConnection остаётся доступным при заблокированном Web Audio. Внешние HTTP заданы локально; выводов о маршрутах
прокси, DNS и IP-утечках этот тест не даёт. Runtime пользователя 154 здесь не запускался.
