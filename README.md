# SecureBrowser для Windows

Менеджер профилей для ручной работы с сайтами, включая Proton Mail. Каждый профиль — отдельная среда WebView2 со своей папкой данных, вкладками, настройками и напоминаниями о посещении.

**Статус: прототип. Сборки, тесты ядра и нативные проверки WebView2 выполняются в Windows CI; полная ручная приёмка интерфейса не завершена.** Актуальная матрица — [приёмка 0.1.53](docs/acceptance-report-0.1.53.md); исходный отчёт 0.1.0 сохранён как исторический.

## Импорт настроек (0.1.53)

Импорт ограничен 1 МиБ и требует подтверждения предпросмотра. Если выбранный файл
исчез или занят другой программой, приложение показывает ошибку и сохраняет
существующие профили. Отмена и закрытие предпросмотра ничего не импортируют.
Новые профили получают свежие идентификаторы, не открываются автоматически и
не переносят сессии, разрешения или учётные данные прокси. Неполные сетевые
настройки блокируют открытие до их заполнения.

Совместимость входа в Cloudflare со строгой защитой: [результаты Windows-проверок и настройки профиля](docs/cloudflare-compatibility.md).

## Восстановление после сбоя (0.1.52)

Оставшийся после падения приложения Runtime продолжает блокировать профиль.
Открытие, сброс и удаление ждут подтверждения его завершения; данные работающего
профиля не удаляются частично из другого экземпляра приложения. Если закрытие
занимает больше 15 секунд, профиль переходит в RecoveryRequired с сохранением
данных и блокировки. Отложенная очистка повторяется после освобождения ресурсов.
Другие профили продолжают работать.

## Завершение исходных функций (0.1.51)

Прокси-настройки считаются применёнными только после HTTP-ответа через среду
профиля: без дискового кэша и ответа сохранённого Service Worker. Ошибки сети,
TLS и proxy authentication сохраняют pending revision; 401/403/429 сайта оставляют
пользователю возможность пройти проверку. Это проверка соединения, а не гарантия
изоляции всех протоколов WebView2.

Меню действий профиля → «Сбросить разрешения сайтов…» удаляет сохранённые
приложением решения отдельно от cookies, входа и вкладок. Открытый профиль сначала
закрывается после подтверждения; несохранённая работа и его загрузки прерываются.
Размер/положение/развёрнутое состояние окна сохраняются глобально и для выбранного
профиля, вне браузерных revision и экспорта. При восстановлении положение
ограничивается рабочей областью основного монитора, чтобы окно оставалось доступным.

Установщик EXE работает для текущего пользователя без административных прав;
ZIP также доступен. Обновление сохраняет профили; при удалении можно оставить
данные или явно удалить их. [Установка, удаление и подпись](docs/installing.md).

## Название и значок (0.1.49)

Приложение называется SecureBrowser. Запускаемый файл — `SecureBrowser.exe`,
архив — `SecureBrowser-<версия>-proxy-win-x64.zip`; свойства файлов, окна и
сохранённые отчёты используют новое имя. Новый значок собран из исходного PNG
512×512: отдельные ICO-размеры 16–256 px для Windows и полный PNG для интерфейса.
Существующие профили и их папки данных продолжают использоваться.

## Загрузки файлов (0.1.48)

Кнопка «Загрузки» открывает список файлов выбранного профиля. При начале скачивания
панель открывается автоматически. Видны объём, проценты, скорость и примерное
оставшееся время; при неизвестном размере показываются полученные байты.
Можно приостановить, продолжить или отменить загрузку, открыть папку готового файла.
Ошибки сети, сервера и записи файла описаны по-русски. Счётчик учитывает отдельные
незавершённые операции, включая паузу и доступное продолжение после ошибки.
Закрытие вкладки, в том числе через `window.close()` сайта, сохраняет скачивание
в фоне. Пауза, продолжение и отмена остаются доступны. Закрытие последней вкладки
при незавершённых загрузках оставляет пустую вкладку и работающий профиль.
Закрытие самого профиля или приложения останавливает все его загрузки. История хранится только до закрытия приложения, отдельно для каждого
профиля; «Очистить завершённые» удаляет записи из списка и сохраняет сами файлы.

## Современный интерфейс (0.1.46)

Светлый интерфейс в духе Firefox: компактная боковая панель с поиском и группами,
округлые вкладки, адресная строка и единый стиль окон. Новый профиль создаётся
кнопкой снизу слева; группы, импорт, экспорт и диагностика — в меню «⋯» над списком.
Меню «⋯» справа от настроек содержит перезапуск, журнал и отпечаток, напоминания,
сброс сессии и удаление. Настройки разделены на «Основное», «Подключение»,
«Язык и время», «Защита» и «Дополнительно»; кнопки сохранения доступны при прокрутке.
Перетаскивание, закрытие колёсиком, сохранение вкладок и сочетания клавиш сохранены.
Это изменение интерфейса: правила защиты и сетевые настройки профилей сохранены.

## Порядок вкладок (0.1.45)

Перетащите заголовок вкладки мышью в нужное место: левая/правая половина соседней
вкладки вставляет до/после неё, область кнопки + — в конец. У края ряда включается
прокрутка. Активная вкладка и страницы сохраняются без перезагрузки; новый порядок
восстанавливается при следующем открытии профиля. Между профилями вкладки не переносятся.

## Авторизация прокси (0.1.44)

Для HTTP-прокси с логином и паролем профиль создаёт отдельный локальный посредник
на 127.0.0.1. WebView2 подключается к нему, а посредник — только к настроенному
прокси. CONNECT передаёт HTTPS без расшифровки; пароль находится лишь во внешнем
запросе к прокси. Каждый туннель получает первую попытку и один повтор при `407`.
GeoIP, параллельные соединения и вкладки больше не расходуют общий лимит профиля.
Обычные HTTP-запросы передаются с паролем прокси однократно: тела запросов повторно
не отправляются. Сайты `401` не получают пароль прокси. Посредник закрывается вместе
с профилем; при недоступном прокси возвращается ошибка без прямого подключения.
В сетевом журнале адресом соединения браузера будет локальный посредник; исходный
адрес прокси остаётся в настройках. Report v27 и collectorHash сохранены.

## Запуск сайтов (0.1.41)

После неуспешной начальной проверки аппаратных разрешений приложение повторно
применяет запреты через служебный контроллер и проверяет их в защищённом документе.
Статус `camera=prompt` означает отсутствие разрешения, а не запрос камеры сайтом.
Если Permissions API остаётся неоднородным, запуск допускается только с установленным
нативным запретом реальных запросов и после удаления конфликтующих сохранённых разрешений.
Обработчик действует в документах и iframe до начальной проверки; исключения камеры
и микрофона сохраняются. Ошибки остальных проверок продолжают блокировать запуск.
Исходные статусы Permissions API остаются видимыми в отчёте.
Windows CI и релиз проверяют Evergreen WebView2 154 или новее, включая запуск
через прокси с автоматическим часовым поясом и восстановление после реального
сброса разрешений, постоянного `camera=prompt` и реальных запросов устройств.
Формат отчёта v27 сохранён; ApplicationVersion 0.1.44.

## Вкладки профиля (0.1.43)

При открытии профиля первая вкладка загружает его начальный URL. Кнопка `+` / `Ctrl+T`
создаёт пустую вкладку; в адресной строке можно открыть любой HTTP/HTTPS сайт.
Кнопка `+` находится сразу справа от последней вкладки; крестик закрытия — внутри
общего прямоугольника каждой вкладки. Длинный ряд вкладок прокручивается горизонтально.
Адрес без схемы открывается через HTTPS. Поисковый сервис автоматически не вызывается.
Есть назад/вперёд (`Alt+←` / `Alt+→`), обновление/остановка (`F5`), переход на сайт
профиля (`⌂`), фокус адреса (`Ctrl+L`), переключение (`Ctrl+Tab`, `Ctrl+Shift+Tab`)
и закрытие вкладки (`×`, `Ctrl+W`). Ссылки `target="_blank"` и `window.open`
открываются в новой вкладке этого же профиля; `window.close` закрывает её.

Все вкладки одного профиля используют одинаковые cookies, хранилище, сетевую среду,
прокси, часовой пояс и исключения защиты. Профили используют разные папки данных.
Настройки и обработчики защиты устанавливаются до первой загрузки сайта; вкладка
показывается после их подготовки. Открытие произвольных сайтов разрешено также
для ранее созданных Proton-профилей. Внешние протоколы и URL с учётными данными
в адресе не открываются.

Клик колёсиком по любой части вкладки закрывает её, в том числе неактивную,
не переключая текущую вкладку. Крестик и Ctrl+W также закрывают вкладку.
При закрытии профиля или приложения сохраняются URL всех оставшихся вкладок,
их порядок, пустые вкладки и выбранная вкладка. Следующий запуск восстанавливает
этот список; страницы загружаются заново с текущими настройками прокси и защиты.
История переходов и несохранённые формы не восстанавливаются.
Закрытые пользователем или через window.close вкладки исключаются. Закрытие
последней вкладки закрывает профиль и сохраняет пустой список; при следующем
открытии такого профиля загружается начальный URL.
Список находится локально в Profiles/<UUID>/tabs.json, вне WebViewData:
сброс данных сайтов сохраняет вкладки, удаление профиля удаляет их.
Повреждённый список игнорируется; неудачный или отменённый запуск не затирает
предыдущий список. Сохранение заменяет файл целиком после записи временной копии.
Диагностика проверяет активную вкладку. Тема и масштаб применяются ко всем вкладкам
профиля; новые вкладки наследуют действующие настройки. ApplicationVersion 0.1.44;
формат отчёта v27, fingerprint ID v2 и схема SQLite v7 сохранены.

Нативный стенд использует production engine и тот же WPF-компонент вкладок:
проверяются first-script защита, общая сессия, изоляция разных профилей,
новое окно/`window.close`, история, закрытие исходной и последней вкладок,
отказ небезопасных URL и устаревшего поколения.
Дополнительно проверяются все 11 аппаратных разрешений при первом скрипте
и после закрытия соседних вкладок. Контроллеры используют постоянный профиль
`Default` среды; запреты удерживаются отдельным служебным контроллером до закрытия профиля;
потеря этого контроллера останавливает профиль.
Данные прежнего именованного `Default` переносятся до запуска браузера с резервной
копией; нативный тест проверяет сохранение cookies и localStorage. Копии остаются
в папке данных профиля (`EBWebView/AllMails-v39-legacy-backup`, а прежняя папка
Runtime Default — `AllMails-v39-previous-default`). Перенос выполняется один раз.

| Сборка | Как получить | Что умеет |
| --- | --- | --- |
| Core | `dotnet build -c Release` | Профили, изоляция, жизненный цикл, настройки, напоминания, импорт/экспорт, сеть System. Профили с прокси заблокированы |
| Experimental proxy | `dotnet build -c Release -p:ExperimentalProxy=true` | Core + HTTP-прокси через недокументированный флаг `--proxy-server`; сетевая изоляция не гарантируется |
| Production candidate с прокси | — | Не заявляется: документированного per-profile proxy API в WebView2 нет, см. [ADR-001](docs/ADR-001-browser-engine.md) |

## Требования

- Windows 11 x64.
- .NET 10 Desktop Runtime (или публикация self-contained, см. ниже).
- Microsoft Edge WebView2 Runtime (Evergreen). Приложение проверяет его при запуске и предлагает страницу установки.
- Для разработки: .NET SDK 10.0.1xx; для тестов JS-guard — Node.js 22+ (CI использует 24).
- Для запуска `build.ps1` — PowerShell 7 или новее.

## Сборка и тесты

```powershell
./build.ps1                       # restore, build Core + Experimental, тесты ядра
./build.ps1 -Publish              # + self-contained win-x64 в artifacts/
dotnet test tests/ProtonProfiles.Core.Tests
node --test tests/webrtc-guard.test.mjs tests/fingerprint.test.mjs tests/audio-guard.test.mjs tests/residual-guard.test.mjs  # Node.js 22+; семантика JS, не проверка WebView2
```

На Linux/macOS собирается только для проверки компиляции (`EnableWindowsTargeting`); это не проверка поведения WebView2.

## Главные решения

- Путь данных: `%LOCALAPPDATA%\ProtonProfiles\Profiles\<UUID>\WebViewData`, только из UUID. Блокировки — в `Locks\`, вне удаляемой папки.
- Инициализация: окружение с опциями → проверка фактического UDF и канала → controller options (постоянный профиль, `ScriptLocale`) → обработчики и настройки → проверки защиты → восстановление вкладок или стартовая страница профиля (по умолчанию `https://mail.proton.me/`).
- Закрытие ждёт `BrowserProcessExited` до 15 с, иначе «Требуется восстановление»; UDF не удаляется и чужие процессы не завершаются.
- Не больше трёх живых окружений; при открытии четвёртого пользователь выбирает, что закрыть.
- Сброс сессии и удаление профиля — локальные действия; они не удаляют аккаунт Proton и не отзывают его сеансы.
- Доступ страниц к WebRTC по умолчанию блокируется ранним скриптом во всех WebView профиля, включая дочерние окна и диагностику; камера и микрофон запрещены. Режим «Разрешить для совместимости» и изменения сетевой политики требуют полного перезапуска профиля. Блокировка страниц не отключает нативный WebRTC. В экспериментальной сборке отдельно доступен флаг `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`; его сетевое действие и покрытие контекстов требуют проверки на Windows. Полное отсутствие утечек не заявляется. См. [WEBRTC_FIX_REPORT.md](WEBRTC_FIX_REPORT.md).
- Пароли и автозаполнение браузера отключены; разрешения хранятся в одной политике приложения (`SavesInProfile = false`).
- Секреты прокси — в диспетчере учётных данных Windows; каждый новый секрет получает новую ссылку.
- Напоминания — локальные отметки «Я проверил ящик», по умолчанию раз в 6 месяцев. Proton рекомендует входить в бесплатный аккаунт хотя бы раз в год (сведения на 3 октября 2026).

## Начальная страница профиля

Кнопка «Создать» открывает одну форму профиля с названием, меткой и любым
HTTP/HTTPS URL. По умолчанию указана страница Proton Mail. Начальный URL
можно менять в настройках любого профиля; живой профиль нужно перезапустить.
Произвольные сайты и их переходы открываются внутри профиля. Отдельной
кнопки тестового профиля больше нет. Внутренние имена файлов, папок данных,
credential references сохранены. Группы добавлены в схему метаданных v5
с резервной копией при обновлении; браузерные данные не удаляются.

В настройках есть «Защита отпечатка → WebGL/WebGPU».
Настройка требует перезапуска и уменьшает раскрытие GPU через эти API, но может
нарушить работу 3D, карт и графических редакторов. Ускорение GPU отключается, поэтому
интерфейс и видео могут работать медленнее. Canvas 2D, Audio, CPU, память и
шрифты остаются доступными. WebView2 использует нативные флаги; результат WebGPU
и покрытие контекстов требуют проверки на конкретном Runtime.

В 0.1.7 добавлен отдельный режим «WebGL/WebGPU + Canvas».
Он сохраняет команды рисования, но нативно запрещает чтение пикселей и экспорт
Canvas/OffscreenCanvas. Это уменьшает раскрытие Canvas-отпечатка и может нарушить
экспорт изображений, редакторы и проверки сайтов. Изменение требует перезапуска.
В диагностике хэш Canvas обозначается как «чтение заблокировано», а результаты
для документа и dedicated worker проверяются отдельно. CPU, память, Audio,
экран/DPI, шрифты и WebView2 Client Hints остаются доступны.

В 0.1.8 появился режим «Защита отпечатка → WebGL/WebGPU + Canvas + Web Audio».
Он дополнительно блокирует создание AudioContext и OfflineAudioContext в документах
через скрипт WebView2 до скриптов страницы. Блокировка проверяется до начального URL;
ошибка блокирует открытие. Доступные для наблюдения документы и фреймы проверяются
после загрузки, нарушение закрывает профиль; устаревший результат или ошибка наблюдения
нарушением не считаются. Это экспериментальная защита Web Audio в документах:
полное покрытие контекстов и всех способов аудиоотпечатка не подтверждено.
API обычного HTML audio/video сохраняются; аудиоэффекты, визуализаторы и сайты,
использующие Web Audio, могут сломаться. В отчёте v5 хэш становится «Web Audio заблокирован»

## Журнал и отпечаток

Кнопка «Журнал и отпечаток…» у открытого профиля открывает окно с тремя вкладками.

- **Соединения**: каждый запрос профиля с момента открытия. Видны время, метод, статус, тип, хост, удалённый IP и порт, протокол (h2, h3, http/1.1), версия TLS и шифр, издатель сертификата, размер, длительность, ошибки и редиректы. Данные берутся из DevTools Network самого WebView2; тела запросов не читаются. При работе через прокси удалённым адресом будет адрес прокси. Значения параметров в URL скрыты (`?token=…`), потому что в них бывают одноразовые токены.
- **Хосты**: сводка по каждому хосту с его IP-адресами, протоколами, TLS и издателем сертификата.
- **IP и отпечаток**: проверка запускается внутри самого профиля, с тем же окружением, User-Agent, языком и сетевым путём, что и почта. Она показывает внешний IP, город, провайдера и часовой пояс IP (ipinfo.io, api.ipify.org), IPv6, доступность API WebRTC в этой странице, заголовки, которые получает сервер (httpbin.org), User-Agent и Client Hints, языки, часовой пояс, экран, WebGL/WebGPU, хэши Canvas и Audio, шрифты, хранилище и разрешения. Есть проверки согласованности: часовой пояс IP и браузера, страна IP и языки, расхождения User-Agent и Client Hints. Внешние HTTP-сервисы вызываются только по открытию этой вкладки. Соединения WebRTC и запросы к STUN/TURN в обычной диагностике не выполняются; проверка маршрута возможна только на [контролируемом стенде](tests/fixture/WEBRTC.md).

В настройках профиля можно задать часовой пояс браузера IANA, например `Europe/Berlin`; пустое поле сохраняет системный пояс. Нужен перезапуск профиля. Настройка применяется через нативный DevTools Protocol до открытия почты, также к дочерним окнам и диагностике; перед открытием основного окна проверяются `Intl` и зимнее/летнее смещение `Date`. Даты напоминаний сохраняют прежний часовой пояс. Для исходного немецкого выхода рекомендуется `Europe/Berlin` и штатный User-Agent; язык менять необязательно.

При сохранении отчёта IP и hostname скрываются по умолчанию; можно снять соответствующую галочку для локальной диагностики. Проверяются также часовой пояс и доступность графических API локального dedicated worker. Ошибочный или пустой ответ IPv6 не считается доказательством отсутствия IPv6.

ID среды v2 исключает скорость сети, RTT и размеры окна. Отдельный `stateFingerprintId` описывает текущее состояние. ID служат для сравнения отчётов этого сборщика, не измеряют уникальность; v2 несопоставим со старым ID. Проверка UA разделяет версию Chromium, бренд и платформу, сопоставляет HTTP-заголовки с JavaScript. Проверки маршрутов IPv4/IPv6, DNS, отказа прокси и полного покрытия контекстов остаются `NotPerformed`. Подробнее: [FINGERPRINT_FIX_REPORT.md](FINGERPRINT_FIX_REPORT.md).

Журнал пишется в `Profiles\<UUID>\Logs\connections-*.tsv`; хранятся последние 10 файлов. Он удаляется вместе с профилем и сохраняется при сбросе сессии. Журнал и отчёт об отпечатке можно сохранить кнопками в окне; в общий отчёт «Диагностика…» они не попадают.

## Ограничения

- Разные UA, языки, часовые пояса и IP не делают аккаунты несвязываемыми; Canvas/графические API и Web Audio можно ограничить экспериментально; шрифты, экран и аппаратные признаки остаются видимыми. Покрытие настройки часового пояса всеми workers и отдельными процессами фреймов требует проверки.
- Скрытый профиль продолжает работать в сети. Уведомления приходят только от открытых профилей.
- Аутентификация Basic на сайтах (401) отменяется: учётные данные прокси никогда не отдаются сайтам.
- Установщик и подпись не подготовлены (этап 3).
- Отладочная сборка позволяет направить профили на тестовый стенд переменными `PP_FIXTURE_ORIGINS` и `PP_FIXTURE_START`; Release их игнорирует.


В 0.1.17 добавлен общий режим «Строгая защита API и оценки сети» (GraphicsPolicy 11).
Он сохраняет режим 10 и нативно отключает WebXR, navigator.cpuPerformance,
performance.measureUserAgentSpecificMemory, захват экрана, выбор аудиовыхода,
SensorExtraClasses и WebNFC. PreciseMemoryInfo принудительно выключен;
обычный performance.memory и deviceMemory не скрываются. Через Browser.setPermission
камера, микрофон, геолокация, accelerometer, gyroscope, magnetometer и MIDI, idle detection и дополнительные экраны
получают denied для всех origin в отдельной среде профиля. Ранее сохранённое
разрешение приложения не отменяет запрет. JS API не подменяются; датчики не запускаются.

Флаг --force-effective-connection-type=4G заменяет измеренные NQE оценки типовыми.
DPR, native getters, реальная скорость загрузок и маршруты сохраняются. RTT/downlink
движок округляет с вариацией по origin; saveData и физический тип соединения этим
флагом не скрываются. Это ограничение данных Network Information API, а не эмуляция
прокси, изменение IP или обещание отсутствия прямого трафика.

Выберите режим вручную, штатный UA и полностью перезапустите профиль.
Видеозвонки, VR, захват экрана, датчики и выбор устройств могут перестать работать.
Отчёт v13 отдельно проверяет дополнительные API, аппаратные разрешения и оценки
сети в документе/worker. Для Window-only API отсутствие в dedicated worker —
NotApplicable. Отдельная residualExposure показывает оставшиеся источники;
дополнительные секции не меняют входные данные ID среды v2.

Экран, RAM, CSS-шрифты, Math, timing, codecs, quota и часть медиаустройств не
скрыты. У RAM и CSS-шрифтов нет подтверждённого общего механизма отключения в

Отчёт v15 сохраняет разделы CSS и программных ограничений после сортировки.

Размеры экрана, Math, timings, codecs, размеры окна и другие способы определения оборудования
остаются доступны; сайты и аккаунты могут связываться по другим данным.
Для применения нужны строгий режим, штатный UA и полный перезапуск профиля.


В 0.1.20 иконка EXE и окон заменена изображением конверта из предоставленного
`email.zip`; постоянный жёлтый баннер в главном окне удалён. Возможности прокси
и границы сетевой проверки по-прежнему описаны в диагностике и документации.

Встроенный сборщик использует нейтральный адрес `https://diagnostics.invalid`
и `Referrer-Policy: no-referrer`. Политика браузера отключает Referer;
нативный Fetch-перехват убирает Origin из GET-запросов к httpbin/ipinfo. Для api.ipify.org и api6.ipify.org
Origin сохраняется с нейтральным адресом: эти сервисы возвращают CORS
allow-origin только при наличии Origin в запросе. Внешние сервисы не получают
название приложения. Заголовки обычных сайтов, POST и CORS preflight сохраняются.
Результат HTTP echo отображается без редактирования. Если сервис требует

## Автоматический часовой пояс по IP (0.1.32)

В настройках каждого профиля доступны «Системный», «Ручной (IANA)» и «Авто по IP».
Для автоматического режима скачайте [GeoLite2 City](https://dev.maxmind.com/geoip/geolite2-free-geolocation-data/)
или GeoIP2 City у MaxMind, распакуйте `.mmdb` и нажмите «Установить / обновить City базу…».
GeoLite2 требует учётную запись MaxMind и соблюдение их лицензии; приложение не запрашивает ключ.
База не включена в ZIP. Country и ASN не подходят, потому что не содержат часовой пояс.
Файл копируется в выбранное поколение `%LOCALAPPDATA%\ProtonProfiles\GeoIP\db-*` и используется всеми профилями.

Перед открытием сайта тот же WebView2-контроллер, с сетью и авторизацией прокси профиля,
запрашивает только публичный IP у `https://api.ipify.org?format=json` и `https://api6.ipify.org?format=json`.
Запрос идёт из собственного `about:blank`, с `Origin: null`, без Referer, cookies, редиректов и кеша;
страницы сервиса не открываются и не выполняют код. Сам IP неизбежно видит сервис определения IP.
GeoIP lookup выполняется полностью локально, IP не записывается в настройки или общий отчёт.
Если доступен один стек, используется он; два доступных стека должны совпасть по часовому поясу.
При недоступном прокси/сервисе, отсутствующей базе/записи или конфликте поясов открытие блокируется.
Повторной попытки напрямую или подстановки системного пояса нет; можно выбрать ручной режим.

Пояс применяется нативно до сайта, включая дочерние окна, фреймы и поддерживаемые workers,
и фиксируется на весь сеанс. Каждое новое открытие заново проверяет IP; обновление базы или смена
выходного IP требует перезапуска профиля. Напоминания и системные часы Windows не меняются.
GeoIP — оценка местоположения IP, а не подтверждение маршрутов: база может быть устаревшей,
а дальнейшая смена IP в работающем соединении автоматически не отслеживается.
Настройки мигрируют SQLite v6 → v7 с резервной копией; старые системные/ручные режимы сохраняются.

## Mailfud Legacy City (0.1.34)

Режим «Авто по IP» принимает [GeoIPCity.dat.gz (IPv4)](https://mailfud.org/geoip-legacy/GeoIPCity.dat.gz)
и [GeoIPCityv6.dat.gz (IPv6)](https://mailfud.org/geoip-legacy/GeoIPCityv6.dat.gz).
Скачайте файлы, в настройках профиля нажмите **«Установить / обновить City базу…»**
и выберите оба сразу. Распаковывать gzip вручную не требуется; `.dat` тоже принимается.
Новый импорт заменяет весь выбранный набор. IPv6-файл Mailfud также содержит IPv4-mapped записи:
он может использоваться отдельно, но обычный IPv4-файл IPv6 не покрывает.
Если IP выхода включает IPv6, а установлен только IPv4-файл, сайт не открывается с сообщением
о недостающей `GeoIPCityv6.dat.gz`. IPv6 не пропускается; системный пояс не подставляется.

Legacy City хранит координаты, а не IANA-пояс. Пояс вычисляется полностью локально
по встроенной GeoTimeZone 6.1.0 и границам timezone-boundary-builder/OpenStreetMap.
Неизвестная/некорректная локация, неоднозначная ячейка у границы поясов или океанский
longitude-only результат блокируют автоматическое открытие; можно выбрать ручной пояс.
Координаты GeoIP бывают приблизительными (включая центр страны), поэтому результат
не является подтверждением физического местоположения или сетевой изоляции.

Установка распаковывает и проверяет файлы в отдельном каталоге, затем атомарно меняет
`GeoIP/active-city.json`: IPv4/IPv6 переключаются вместе. Ошибка сохраняет активную базу.
Поколения ручного импорта хранятся локально; неактивные `GeoIP/db-*` можно удалить после закрытия приложения.
Сам IP и координаты не добавляются в общий отчёт. В отчёте показаны формат, дата и источник пояса.
Старые City MMDB, установленные в 0.1.32, продолжают работать; схема SQLite v7 и формат отчёта v24 сохранены.
Ручной импорт локальных файлов не добавляет сетевые запросы.
Mailfud конвертирует GeoLite2: условия исходной [GeoLite2 EULA](https://www.maxmind.com/en/geolite2/eula)
применяются к этим данным. Реальные IP-базы в ZIP не включены.

## Автообновление Mailfud (0.1.35)

В настройках любого профиля, в блоке «Локальная база GeoIP», включите
**«Автообновление Mailfud каждые 7 дней»**. Переключатель общий для всех профилей,
по умолчанию выключен и сохраняется сразу, независимо от кнопок сохранения/отмены профиля.
Включение сразу запускает скачивание, если обновление уже требуется. Кнопка
**«Скачать Mailfud / обновить сейчас»** работает также при выключенном расписании.
Оба действия устанавливают Mailfud IPv4 + IPv6 вместо выбранного набора, включая MMDB.

Скачивание использует **системную сеть Windows**, включая её системный прокси, если он задан;
прокси профилей и их учётные данные не используются. Mailfud видит IP этого соединения.
Запрашиваются только два фиксированных HTTPS URL, без cookies, Referer, авторизации сайта,
редиректов и выполнения кода. TLS-проверка сертификата сохраняется.
Определение IP при открытии сайта по-прежнему идёт через сеть самого профиля.

Следующее обновление планируется через 7 суток после успешной проверки и установки.
Проверка срока выполняется при запуске и каждые 15 минут во время работы приложения.
Когда приложение закрыто, никаких фоновых задач Windows нет; пропущенное обновление выполняется
при следующем запуске. После ошибки — повтор через сутки, либо вручную «обновить сейчас».
Последний результат и расписание сохраняются в `GeoIP/mailfud-update.json`.

IPv4/IPv6 скачиваются во временный каталог и проверяются полностью; обе даты из metadata
должны совпасть. Более старое поколение, повреждённый gzip/DAT, HTTP-ошибка, редирект,
пустой/слишком большой ответ или тайм-аут сохраняют прежнюю активную базу.
Общий предел попытки — 8 минут, сетевой запрос — 3 минуты, файл — 256 МБ до/после распаковки.
Смена активной базы происходит атомарно. Одновременные экземпляры приложения не скачивают параллельно.
Выключение расписания/закрытие приложения отменяет незавершённую загрузку; ручной импорт выключает
расписание, а его результат не заменяется опоздавшей загрузкой. Старые поколения автообновления
удаляются после успешной замены; поколения ручного импорта сохраняются.
Открытые профили сохраняют свой часовой пояс до полного перезапуска. SQLite v7/report v24 сохранены.

## Часы без публичного маркера и видеотелеметрия (0.1.36)

В строгом режиме у обёрток часов больше нет общедоступного `Symbol.for`-маркера.
Проверка защиты требует, чтобы заданная `Performance.mark` метка `133.375` и её
сериализация действительно округлялись до `100`. Случайное совпадение текущего времени
с границей 100 мс не подтверждает защиту. Повторная установка сохраняет ограничения.
Обёртки JavaScript и их дескрипторы по-прежнему обнаружимы.

Без исключения **«Точные часы, временные метки и видеостатистика»** закрываются
`HTMLVideoElement.requestVideoFrameCallback`, `cancelVideoFrameCallback`,
`getVideoPlaybackQuality`, `webkitDecodedFrameCount` и `webkitDroppedFrameCount`.
Обычное HTML-видео и звук, `play`, `pause`, `load` и поддержка кодеков сохраняются.
Обработка видео по кадрам, статистика воспроизведения и некоторые видеоплееры могут потребовать
этого исключения и полного перезапуска профиля. Оно также возвращает точные часы.

Отчёт повышен до v25: видеотелеметрия проверяется отдельно в документе и фреймах;
worker без HTMLVideoElement обозначается NotApplicable. Проверка не запускает видео
и не читает аппаратные счётчики. Нативный Windows-стенд отдельно воспроизводит собственный
короткий VP8 WebM до/после защиты, проверяет реальный callback/quality до ограничения,
отсутствие API после и восстановление через исключение. Физическое разрешение,
DOM-шрифты, косвенные тайминги, скорость декодирования и общий математический отпечаток остаются доступны.
SQLite v7, алгоритм ID среды v2 и автообновление GeoIP раз в 7 дней сохранены.

## Дополнительные временные метки (0.1.37)

Строгий режим огрубляет до 100 мс отдельные поля Long Animation Frame и Script Timing:
время начала отрисовки/выполнения, блокировки, layout/style и пауз. Также огрублены
paint/presentation и Element Timing. Нативный `toJSON()` может обходить JavaScript getters;
его результат обрабатывается отдельно, включая вложенные `scripts` и `userTimingEntries`.
Явные пользовательские `PerformanceMark.detail` и прочие нетайминговые данные сохранены.
`PerformanceObserver`, callback-планирование, отрисовка и Web Crypto остаются доступны.

Исключение **«Точные часы, временные метки и видеостатистика»** возвращает эти тайминги
после полного перезапуска профиля. Обёртки обнаружимы; профилировщики могут потерять точность.
Отчёт v26 проверяет фиксацию дополнительных дескрипторов, если они доступны, вместе с
поведенческой проверкой явной метки. Сам отчёт не создаёт нагрузку или длинные кадры.
Windows-стенд отдельно создаёт настоящий длинный кадр с таймингами скриптов до/после защиты
и при исключении. Это не скрывает косвенные часы, физическое разрешение и DOM-шрифты.
SQLite v7 и fingerprint ID v2 сохранены.

## Положение устройства и Viewport Segments (0.1.38)

Строгий режим нативно задаёт Device Posture `continuous`. Флаг Blink `ViewportSegments`
отключает Viewport API, CSS media queries о сегментах и их CSS environment variables.
Сайт получает обычное положение устройства, а доступ к геометрии разделения ограничен.
Физический размер экрана и прочие геометрические пути остаются доступны.
Реальные CSS-правила, `matchMedia`, `env()` и доступные нативные getters проверяются вместе;
отсутствующие данные не засчитываются как защита. Неподдерживаемый синтаксис `env()` отмечается
явно; fallback проверяется, если синтаксис доступен. Worker без документа — NotApplicable.

Исключение **«Реальная рабочая область, положение устройства и сегменты»** возвращает эти
каналы после полного перезапуска профиля. Это прежний бит ScreenWorkArea; SQLite v7 сохранён.
В других режимах аппаратные сведения через эти API сохраняются. CSS для сгиба/двух экранов
может потребовать исключения; обычный адаптивный viewport и отрисовка сохранены.
Отчёт v27 показывает отдельный displayPosture. Нативный Windows-стенд включает folded
и разделитель 8px, проверяет CSS/JS/env до защиты и нативное ограничение с восстановлением
через исключение. ID среды v2 и остальные ограничения сохранены.

HDR через `dynamic-range`/`video-dynamic-range` не скрывается: общий CDP media override
не предоставляет проверенного управления HDR. `color-gamut: srgb` этого не доказывает.
