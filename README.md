# Proton Profiles для Windows

Менеджер профилей для ручной работы с существующими аккаунтами Proton Mail через официальный веб-интерфейс. Каждый профиль — отдельный WebView2-окружение со своей папкой данных, своими настройками и напоминаниями о посещении. Реализация по спецификации v1.1 (`proton_profiles_windows_spec_en.md`).

**Статус: прототип (этапы 1–2). Собирается, ядро покрыто тестами, на Windows не запускался.** Подробно — [docs/acceptance-report.md](docs/acceptance-report.md).

| Сборка | Как получить | Что умеет |
| --- | --- | --- |
| Core | `dotnet build -c Release` | Профили, изоляция, жизненный цикл, настройки, напоминания, импорт/экспорт, сеть System. Профили с прокси заблокированы |
| Experimental proxy | `dotnet build -c Release -p:ExperimentalProxy=true` | Core + HTTP-прокси через флаг `--proxy-server`. Помечена в интерфейсе как экспериментальная, сетевая изоляция не гарантируется |
| Production candidate с прокси | — | Не заявляется: документированного per-profile proxy API в WebView2 нет, см. [ADR-001](docs/ADR-001-browser-engine.md) |

## Требования

- Windows 11 x64.
- .NET 10 Desktop Runtime (или публикация self-contained, см. ниже).
- Microsoft Edge WebView2 Runtime (Evergreen). Приложение проверяет его при запуске и предлагает страницу установки.
- Для разработки: .NET SDK 10.0.1xx; для тестов JS-guard — Node.js 22+ (CI использует 24).

## Сборка и тесты

```powershell
./build.ps1                       # restore, build Core + Experimental, тесты ядра
./build.ps1 -Publish              # + self-contained win-x64 в artifacts/
dotnet test tests/ProtonProfiles.Core.Tests
node --test tests/webrtc-guard.test.mjs tests/fingerprint.test.mjs  # Node.js 22+; семантика JS, не проверка WebView2
```

На Linux/macOS собирается только для проверки компиляции (`EnableWindowsTargeting`); это не проверка поведения WebView2.

## Главные решения

- Путь данных: `%LOCALAPPDATA%\ProtonProfiles\Profiles\<UUID>\WebViewData`, только из UUID. Блокировки — в `Locks\`, вне удаляемой папки.
- Инициализация строго по §4.5: окружение с опциями → проверка фактического UDF и канала → controller options (постоянный профиль, `ScriptLocale`) → обработчики и настройки → навигация на `https://mail.proton.me/`.
- Закрытие ждёт `BrowserProcessExited` до 15 с, иначе «Требуется восстановление»; UDF не удаляется и чужие процессы не завершаются.
- Не больше трёх живых окружений; при открытии четвёртого пользователь выбирает, что закрыть.
- Сброс сессии и удаление профиля — локальные действия; они не удаляют аккаунт Proton и не отзывают его сеансы.
- Доступ страниц к WebRTC по умолчанию блокируется ранним скриптом во всех WebView профиля, включая дочерние окна и диагностику; камера и микрофон запрещены. Режим «Разрешить для совместимости» и изменения сетевой политики требуют полного перезапуска профиля. Блокировка страниц не отключает нативный WebRTC. В экспериментальной сборке отдельно доступен флаг `--force-webrtc-ip-handling-policy=disable_non_proxied_udp`; его сетевое действие и покрытие контекстов требуют проверки на Windows. Полное отсутствие утечек не заявляется. См. [WEBRTC_FIX_REPORT.md](WEBRTC_FIX_REPORT.md).
- Пароли и автозаполнение браузера отключены; разрешения хранятся в одной политике приложения (`SavesInProfile = false`).
- Секреты прокси — в диспетчере учётных данных Windows; каждый новый секрет получает новую ссылку.
- Напоминания — локальные отметки «Я проверил ящик», по умолчанию раз в 6 месяцев. Proton рекомендует входить в бесплатный аккаунт хотя бы раз в год (сведения на 3 октября 2026).

## Тестовые профили

Кнопка «Тестовый профиль…» создаёт отдельный профиль с произвольным HTTP/HTTPS URL,
включая локальные стенды и нестандартные порты. Веб-страница, редиректы и дочерние
окна открываются внутри этого профиля. Начальный URL меняется в настройках и требует
перезапуска. Почтовые профили сохраняют ограничения Proton; их данные не копируются.
Новый тестовый профиль остаётся закрытым, пока вы выбираете прокси и другие настройки.
Напоминания о почте в нём скрыты. Схемы file/data/javascript и системные обработчики
не поддерживаются; логин и пароль в URL не допускаются.

В настройках есть «Защита отпечатка → WebGL/WebGPU».
Настройка требует перезапуска и уменьшает раскрытие GPU через эти API, но может
нарушить работу 3D, карт и графических редакторов. Ускорение GPU отключается, поэтому
интерфейс и видео могут работать медленнее. Canvas 2D, Audio, CPU, память и
шрифты остаются доступными. WebView2 использует нативные флаги; результат WebGPU
и покрытие контекстов требуют проверки на конкретном Runtime.

В 0.1.7 добавлен отдельный режим «WebGL/WebGPU + Canvas».
Он сохраняет команды рисования, но нативно запрещает чтение пикселей и экспорт
Canvas/OffscreenCanvas. Это уменьшает раскрытие Canvas-отпечатка и может нарушить
экспорт изображений, редакторы и проверки сайтов. Изменение требует перезапуска.
В диагностике хэш Canvas обозначается как «чтение заблокировано», а результаты
для документа и dedicated worker проверяются отдельно. CPU, память, Audio,
экран/DPI, шрифты и WebView2 Client Hints остаются доступны.

В 0.1.8 появился режим «Защита отпечатка → WebGL/WebGPU + Canvas + Web Audio».
Он дополнительно блокирует создание AudioContext и OfflineAudioContext в документах
через скрипт WebView2 до скриптов страницы. Блокировка проверяется до начального URL;
ошибка блокирует открытие. Доступные для наблюдения документы и фреймы проверяются
после загрузки, нарушение закрывает профиль; устаревший результат или ошибка наблюдения
нарушением не считаются. Это экспериментальная защита Web Audio в документах:
полное покрытие контекстов и всех способов аудиоотпечатка не подтверждено.
API обычного HTML audio/video сохраняются; аудиоэффекты, визуализаторы и сайты,
использующие Web Audio, могут сломаться. В отчёте v5 хэш становится «Web Audio заблокирован»
только при подтверждённой блокировке. Для dedicated worker естественное отсутствие
Window Web Audio API обозначается NotApplicable. CPU, RAM, шрифты, экран и Math
остаются видимыми. Выбор режима требует полного перезапуска профиля.

В 0.1.9 добавлен режим «Графика/Canvas/Audio + DPR 1».
Он включает предыдущие ограничения и задаёт базовый масштаб устройства 1 через
нативный общий флаг Chromium --force-device-scale-factor=1. JavaScript getters
не заменяются. Размеры экрана вычисляются движком с новым масштабом; responsive viewport сохраняется; масштаб
браузера учитывается отдельно. Старт проверяет DPR и согласованность CSS media queries
до целевого URL; ошибка блокирует открытие. Новый режим и изменение масштаба в нём
требуют полного перезапуска. Полное покрытие и отсутствие побочных признаков DPI
не подтверждены. CPU/RAM, шрифты, экран, Math и Client Hints остаются видимыми.
Режим может изменить размер/резкость элементов и поведение при нескольких мониторах.

В 0.1.10 добавлен режим «Графика/Canvas/Audio/DPR + без речи». Он включает предыдущие
ограничения и отключает Speech Synthesis общим нативным флагом Blink
`--disable-blink-features=ScriptedSpeechSynthesis`. Сайты теряют доступ к списку
голосов ОС и озвучке текста через этот API. При старте проверяется отсутствие
`speechSynthesis`, `SpeechSynthesis`, `SpeechSynthesisUtterance` и `SpeechSynthesisVoice`
до целевого URL; ошибка блокирует открытие. Отчёт v7 отдельно показывает результат
для документа; естественное отсутствие Window API в worker — NotApplicable.
Настройку нужно выбрать вручную и полностью перезапустить профиль. Прежние режимы
сохраняются. HTML audio/video API остаются доступны; CPU/RAM, шрифты, экран, Math
и Client Hints остаются видимыми.

В 0.1.11 добавлен режим «Предыдущая защита + без UA Client Hints». Он включает
ограничения режима без речи и ограничивает UA Client Hints через нативный CDP,
без метаданных UA. Штатный User-Agent сохраняет своё значение. Режим требует UA «По умолчанию»;
сочетание с UA «Свой» отклоняется до открытия сайта, поскольку WebView2 сохраняет
исходный UA в ServiceWorker.
Связанные фреймы и workers получают настройку до запуска скриптов.
JavaScript API не подменяются.
SharedWorker отключён нативно, поскольку WebView2 не подключает его к сессии страницы
до запуска; сайты, которым нужен этот API, могут перестать работать.
Перед целевым URL основной и диагностический контроллеры проверяют результат в
локальной HTTPS-странице, ответ которой отдаёт приложение; при неудаче открытие
блокируется. Поведение зависит от Runtime. Детектирование браузера некоторыми сайтами
может измениться. Настройка включается вручную и требует полного перезапуска профиля.
Отчёт v8 отдельно показывает наблюдения UA Client Hints документа, dedicated worker
и HTTP echo; отсутствие ответа сервера не подтверждает удаление заголовков.
CPU/RAM, шрифты, размеры экрана, Math и обычный User-Agent остаются доступны.

В 0.1.13 опубликован режим «Предыдущая защита + без Local Font Access»: он сохраняет
ограничения режима без UA Client Hints и нативно отключает Blink `FontAccess`.
`queryLocalFonts` и `FontData` становятся недоступны: сайт не может получить полный
список локальных шрифтов и прочитать их файлы через этот API. Определение шрифтов
через CSS/Canvas.measureText сохраняется; набор установленных шрифтов этим режимом
не скрывается. Возможна несовместимость с редакторами и выбором локальных шрифтов.
Нужен UA «По умолчанию» и полный перезапуск профиля. До целевого URL основной и
диагностический контроллеры проверяют отсутствие API в защищённом документе.

Начиная с v9 отчёт содержит `applicationVersion` из версии сборки EXE,
`collectorHash` встроенной страницы и активный `requestedSettings.graphicsPolicy`.
Версия формата отчёта и версия приложения — разные значения. Страница отдаётся
из ресурса сборки с `Cache-Control: no-store`; каждый запуск получает новый URL.
Старый или несовместимый отчёт нельзя сохранить через окно диагностики.
Local Font Access проверяется отдельно: естественное отсутствие Window API в worker
остаётся `NotApplicable`, а неполные данные — `NotPerformed`.

В 0.1.14 добавлен режим «Предыдущая защита + округление CPU»: он сохраняет
режим без Local Font Access и нативно применяет
`Emulation.setHardwareConcurrencyOverride` в документах и связанных workers.
Исходное `navigator.hardwareConcurrency` округляется вниз до 1, 2, 4 или 8;
12/16/32 становятся 8, 6 становится 4, 2 остаётся 2. Значение никогда не повышается.
Нативный getter сохраняется; JS-подмена navigator отсутствует. При старте основной
и диагностический контроллеры проверяют ожидаемое число и getter до целевого URL.
Некоторые сайты будут запускать меньше параллельных задач. Физический CPU,
результаты измерения производительности и объём RAM эта настройка не скрывает.
Нужен штатный UA и полный перезапуск профиля; прежние режимы не меняются автоматически.

Текущий формат отчёта — v16, версия приложения — 0.1.20. В отчёте добавлены
`expectedHardwareConcurrency`, наблюдения `cpu` и отдельные результаты проверки
документа/dedicated worker. Пустое наблюдение или другой bucket не подтверждают
нормализацию. ID среды v2 меняется, когда меняется наблюдаемое число потоков;
версия приложения и текст пояснений по-прежнему не входят в этот ID.

В 0.1.15 добавлен режим «Предыдущая защита + без аппаратных API».
Он сохраняет режим CPU и нативно отключает Blink `WebBluetooth`, `WebUSB`,
`WebHID` и `Serial`. Сайты не смогут обращаться к Bluetooth/USB/HID-устройствам
и последовательным портам через эти API, включая ранее разрешённые устройства.
Не работают сайты для подключения оборудования. Режим включается вручную,
требует штатного UA и полного перезапуска профиля. Остальные режимы сохраняются.
Проверка до целевого URL требует отсутствия navigator entry points и конструкторов
в защищённом документе; отчёт v11 проверяет также dedicated worker.
Наблюдение не перечисляет устройства, не читает их сведения и не запрашивает
разрешения. RAM, размеры экрана, CSS-шрифты, медиаустройства и другие способы
определения оборудования остаются доступны; полный охват контекстов не заявляется.
Новые наблюдения аппаратных API не добавлены во входные данные ID среды v2.

В 0.1.16 добавлен режим «Предыдущая защита + без API нагрузки CPU».
Он сохраняет аппаратные ограничения и нативно отключает Blink `ComputePressure`:
`PressureObserver` и `PressureRecord` становятся недоступны в документе и
поддерживаемых workers. Сайт не сможет наблюдать нагрузку через этот API;
адаптация сайта к нагрузке может перестать работать. Обычные benchmarks, физический
CPU, RAM, экран и CSS-шрифты остаются доступны. Нужен штатный UA, ручной выбор
режима и полный перезапуск профиля; прежние режимы сохраняются.
Bootstrap проверяет отсутствие API в защищённом документе до целевого URL.
Отчёт v12 отдельно проверяет документ/dedicated worker; наблюдатель не создаёт
PressureObserver и не запускает измерений. ServiceWorker естественно не имеет
этого API; полное покрытие всех контекстов не заявляется. Новые наблюдения и
описания Compute Pressure не добавлены во входные данные ID среды v2.

Тестовые URL по умолчанию исключены из экспорта настроек. Их включение — отдельный
выбор, поскольку полный URL может содержать токены. Импортированный тестовый профиль
без URL остаётся тестовым и не открывается до настройки.

## Журнал и отпечаток

Кнопка «Журнал и отпечаток…» у открытого профиля открывает окно с тремя вкладками.

- **Соединения**: каждый запрос профиля с момента открытия. Видны время, метод, статус, тип, хост, удалённый IP и порт, протокол (h2, h3, http/1.1), версия TLS и шифр, издатель сертификата, размер, длительность, ошибки и редиректы. Данные берутся из DevTools Network самого WebView2; тела запросов не читаются. При работе через прокси удалённым адресом будет адрес прокси. Значения параметров в URL скрыты (`?token=…`), потому что в них бывают одноразовые токены.
- **Хосты**: сводка по каждому хосту с его IP-адресами, протоколами, TLS и издателем сертификата.
- **IP и отпечаток**: проверка запускается внутри самого профиля, с тем же окружением, User-Agent, языком и сетевым путём, что и почта. Она показывает внешний IP, город, провайдера и часовой пояс IP (ipinfo.io, api.ipify.org), IPv6, доступность API WebRTC в этой странице, заголовки, которые получает сервер (httpbin.org), User-Agent и Client Hints, языки, часовой пояс, экран, WebGL/WebGPU, хэши Canvas и Audio, шрифты, хранилище и разрешения. Есть проверки согласованности: часовой пояс IP и браузера, страна IP и языки, расхождения User-Agent и Client Hints. Внешние HTTP-сервисы вызываются только по открытию этой вкладки. Соединения WebRTC и запросы к STUN/TURN в обычной диагностике не выполняются; проверка маршрута возможна только на [контролируемом стенде](tests/fixture/WEBRTC.md).

В настройках профиля можно задать часовой пояс браузера IANA, например `Europe/Berlin`; пустое поле сохраняет системный пояс. Нужен перезапуск профиля. Настройка применяется через нативный DevTools Protocol до открытия почты, также к дочерним окнам и диагностике; перед открытием основного окна проверяются `Intl` и зимнее/летнее смещение `Date`. Даты напоминаний сохраняют прежний часовой пояс. Для исходного немецкого выхода рекомендуется `Europe/Berlin` и штатный User-Agent; язык менять необязательно.

При сохранении отчёта IP и hostname скрываются по умолчанию; можно снять соответствующую галочку для локальной диагностики. Проверяются также часовой пояс и доступность графических API локального dedicated worker. Ошибочный или пустой ответ IPv6 не считается доказательством отсутствия IPv6.

ID среды v2 исключает скорость сети, RTT и размеры окна. Отдельный `stateFingerprintId` описывает текущее состояние. ID служат для сравнения отчётов этого сборщика, не измеряют уникальность; v2 несопоставим со старым ID. Проверка UA разделяет версию Chromium, бренд и платформу, сопоставляет HTTP-заголовки с JavaScript. Проверки маршрутов IPv4/IPv6, DNS, отказа прокси и полного покрытия контекстов остаются `NotPerformed`. Подробнее: [FINGERPRINT_FIX_REPORT.md](FINGERPRINT_FIX_REPORT.md).

Журнал пишется в `Profiles\<UUID>\Logs\connections-*.tsv`; хранятся последние 10 файлов. Он удаляется вместе с профилем и сохраняется при сбросе сессии. Журнал и отчёт об отпечатке можно сохранить кнопками в окне; в общий отчёт «Диагностика…» они не попадают.

## Ограничения

- Разные UA, языки, часовые пояса и IP не делают аккаунты несвязываемыми; Canvas/графические API и Web Audio можно ограничить экспериментально; шрифты, экран и аппаратные признаки остаются видимыми. Покрытие настройки часового пояса всеми workers и отдельными процессами фреймов требует проверки.
- Скрытый профиль продолжает работать в сети. Уведомления приходят только от открытых профилей.
- Аутентификация Basic на сайтах (401) отменяется: учётные данные прокси никогда не отдаются сайтам.
- Установщик и подпись не подготовлены (этап 3).
- Отладочная сборка позволяет направить профили на тестовый стенд переменными `PP_FIXTURE_ORIGINS` и `PP_FIXTURE_START`; Release их игнорирует.


В 0.1.17 добавлен общий режим «Строгая защита API и оценки сети» (GraphicsPolicy 11).
Он сохраняет режим 10 и нативно отключает WebXR, navigator.cpuPerformance,
performance.measureUserAgentSpecificMemory, захват экрана, выбор аудиовыхода,
SensorExtraClasses и WebNFC. PreciseMemoryInfo принудительно выключен;
обычный performance.memory и deviceMemory не скрываются. Через Browser.setPermission
камера, микрофон, геолокация, accelerometer, gyroscope, magnetometer и MIDI, idle detection и дополнительные экраны
получают denied для всех origin в отдельной среде профиля. Ранее сохранённое
разрешение приложения не отменяет запрет. JS API не подменяются; датчики не запускаются.

Флаг --force-effective-connection-type=4G заменяет измеренные NQE оценки типовыми.
DPR, native getters, реальная скорость загрузок и маршруты сохраняются. RTT/downlink
движок округляет с вариацией по origin; saveData и физический тип соединения этим
флагом не скрываются. Это ограничение данных Network Information API, а не эмуляция
прокси, изменение IP или обещание отсутствия прямого трафика.

Выберите режим вручную, штатный UA и полностью перезапустите профиль.
Видеозвонки, VR, захват экрана, датчики и выбор устройств могут перестать работать.
Отчёт v13 отдельно проверяет дополнительные API, аппаратные разрешения и оценки
сети в документе/worker. Для Window-only API отсутствие в dedicated worker —
NotApplicable. Отдельная residualExposure показывает оставшиеся источники;
дополнительные секции не меняют входные данные ID среды v2.

Экран, RAM, CSS-шрифты, Math, timing, codecs, quota и часть медиаустройств не
скрыты. У RAM и CSS-шрифтов нет подтверждённого общего механизма отключения в
штатном WebView2; фиксирование экрана только в top frame не проходит проверку
cross-origin iframe. Полное сокрытие требует иного движка/изоляции окружения,
а не добавления недействующих флагов. Подробный итог: FINGERPRINT_FIX_REPORT.md.


В 0.1.18 строгий режим (GraphicsPolicy 11) также задаёт стандартные CSS-предпочтения,
семейства generic-шрифтов, размеры по умолчанию 16/13 и масштаб текста ОС 1.
Отрисовка CSS local(...) ограничена средствами движка. Определение наличия шрифта
через FontFace.load(), явные имена установленных шрифтов и шрифты в workers
остаются доступны; это не общий font allowlist. Неподдерживаемые media features
отмечаются null; масштаб текста проверяется на странице с meta text-scale.
Отчёт v14 добавляет фактические наблюдения и standardDefaultsMainDocument;
естественное отсутствие документных настроек в worker — NotApplicable.
В строгом режиме нативный обработчик WebView2 также удаляет Sec-CH-* и прежние
Client Hints (Device-Memory, DPR, Width, Viewport-Width/Height, RTT, Downlink, ECT).
Это ограничивает HTTP-канал раскрытия; navigator.deviceMemory остаётся нативным.
Обычный HTTP echo без Accept-CH не доказывает действие обработчика: диагностика
не выставляет по одному отсутствию заголовков новый Pass.
Выберите «Строгая защита API, сети и CSS», штатный UA и полностью перезапустите
профиль. Новые настройки могут менять оформление и используемые сайтом шрифты.
RAM bucket, физический экран, Math, codecs, Battery/Gamepad и косвенные измерения
не заменяются константами. Подробнее: FINGERPRINT_DEFAULTS_RESEARCH.md.


В 0.1.19 строгий режим 11 сохраняет согласованные нативные размеры Screen,
responsive viewport и масштаб страницы. RAM bucket 8 задаётся
программно: у WebView2 нет нативного CDP override deviceMemory. JavaScript
изменения обнаружимы, физическая память другими путями не скрывается.
Скриптом закрываются Battery/Gamepad, mediaDevices/MediaCapabilities, оставшиеся
датчики, IdleDetector, расширенные экраны, performance.memory и storage.estimate.
Создание FontFace с источником local запрещено; URL и бинарные шрифты сохраняются.
Документы получают guard до своих скриптов; dedicated workers
приостанавливаются до первого скрипта, получают guard и проверяются перед запуском.
ServiceWorker API закрыт; новые и обнаруженные старые targets останавливаются,
а page requests обходят сохранённые workers нативно. Офлайн-режим и фоновые
функции сайтов могут перестать работать. Регистрации/хранилище не удаляются.
Поведение реально проверяется Windows WebView2 стендом, а не только mock-тестом.

Строгий режим с HTTP-прокси убирает implicit loopback bypass, выключает QUIC
и запрещает локальное разрешение всех имён, кроме узла прокси. Ограничение
непроксированного WebRTC UDP применяется автоматически. Локальный Windows стенд
проверяет прокси на IPv4/IPv6, HTTPS CONNECT и отказ прокси без прямого fallback.
Проверка пользовательского маршрута/DNS/WebRTC по JSON остаётся NotPerformed.

Отчёт v15 сохраняет разделы CSS и программных ограничений после сортировки.
Отдельно показывает нативные и программные ограничения. Явные CSS/DOM-шрифты,
Размеры экрана, Math, timings, codecs, размеры окна и другие способы определения оборудования
остаются доступны; сайты и аккаунты могут связываться по другим данным.
Для применения нужны строгий режим, штатный UA и полный перезапуск профиля.


В 0.1.20 иконка EXE и окон заменена изображением конверта из предоставленного
`email.zip`; постоянный жёлтый баннер в главном окне удалён. Возможности прокси
и границы сетевой проверки по-прежнему описаны в диагностике и документации.

Встроенный сборщик использует `Referrer-Policy: no-referrer`. Хост убирает
`Origin` и `Referer` только из его внешних GET Fetch/XHR-запросов с origin
`https://diagnostics.invalid`. Запросы обычных сайтов, POST и CORS
preflight сохраняют свои заголовки. Это исключает название приложения из
диагностических запросов; результат HTTP echo сохраняется без редактирования.
Если сервис требует Origin и отклоняет запрос, проверка покажет ошибку.
У некоторых публичных сервисов запросы без Origin не поддерживаются.

Для api.ipify.org и api6.ipify.org Origin сохраняется с нейтральным адресом
`https://diagnostics.invalid`: эти сервисы возвращают CORS allow-origin только
при наличии Origin в запросе. Внешние сервисы не получают название приложения;
Referer отсутствует. Для httpbin/ipinfo Origin удалён. Это не глобальная
подмена origin сайтов и не изменение CORS-ответов. Без-Origin запросы к
httpbin/ipinfo и нейтральный Origin к ipify проверены по публичным HTTP-ответам
из cloud environment; это не проверка маршрута пользовательского прокси.
