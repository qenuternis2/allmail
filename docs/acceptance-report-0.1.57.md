# Приёмка SecureBrowser 0.1.57

Дата: 8 октября 2026. Изменение касается завершения загрузок и текста статусов.
Пользователь подтвердил: при зависшем «Сохранение файла…» конечный EXE уже есть
на диске. Точная причина на его ПК не воспроизведена. До изменений Linux build
прошёл без предупреждений/ошибок; 667 Core tests прошли без пропусков.

Добавлен резервный источник завершения: пассивный `Page.downloadProgress`
после существующего `Page.enable`, без `setDownloadBehavior`, смены сети
или отключения проверки файлов. GUID берётся из `Page.downloadWillBegin`,
а событие учитывается только для известной загрузки данного контроллера.
Сохраняется нативный Completed; резервный путь используется только при
InProgress, без паузы/отмены, после терминального `completed` и проверки
конечного пути, размера и возможности открыть файл без совместной записи.
Проверка файла выполняется вне UI/COM потока; одновременно разрешена одна
проверка на загрузку, результат прежней native Range operation не принимается.
Нативный Interrupted, в том числе ошибки безопасности, не переопределяется.
Неизвестный Runtime без события остаётся на штатном источнике статуса.

100% больше не сопровождаются «ожидание данных»/нулевой сетевой скоростью.
При ожидании завершения более 30 секунд появляется объяснение. Загрузка
не отменяется по таймауту, файлы не изменяются и не запускаются автоматически.
Публичные интерфейсы, профили, proxy, установка и update не менялись.

Новые проверки в Windows fixture:

- `DownloadCompletionSmoke`: устаревшее InProgress, правильный конечный файл,
  задержанный счётчик байтов, неизвестная длина, пустой файл; отсутствие события
  при 100% и готовом старом файле, Interrupted/пауза/отмена, несовпадение пути
  или размера, эксклюзивная блокировка и повтор после освобождения, неполный/
  отсутствующий/временный файл, некорректные/дробные/переполненные protocol данные.
- `DownloadsSmoke`: реальное пассивное событие завершения с GUID и размером
  HTTP Range загрузки после закрытия исходной вкладки. Существующие проверки
  параллельных/unknown-size/blob/repeated downloads, pause/resume/cancel,
  профильной изоляции и освобождения фоновых контроллеров сохранены.

Итоговый [Windows 11 CI](https://github.com/qenuternis2/allmail/actions/runs/37738434840)
успешно проверил `88c849b`: обе поставки, 667 Core без пропусков, 108 JS,
новые policy/protocol проверки, все native сценарии, DPI и все 5 операций
установщика. [Evidence](security-evidence/windows11-0.1.57.json).
DPI 100/125% — настоящий DesktopScale; 150/200% — SyntheticWM_DPICHANGED.
Первый [прогон](https://github.com/qenuternis2/allmail/actions/runs/37737033787)
`50411a0` также прошёл; после него проверка файла перенесена вне UI потока,
поэтому итоговый изменённый код отдельно проверен полностью.
Сборка smoke на Linux прошла; WPF/WebView2 исполнялись в Windows VM.
Релизный workflow дополнительно проверит точный version tag перед публикацией.

Полная матрица A01–A23 и ранее оставшиеся ручные проверки:
[приёмка 0.1.56](acceptance-report-0.1.56.md). Новые тесты не закрывают
пункты реальных аккаунтов/полной DNS и UDP изоляции/физических DPI 150/200%,
multi-monitor и стандартного неадминистративного токена автоматически.
Установщик unsigned; причина таймаута удаления данных в первой попытке
релиза 0.1.56 остаётся неподтверждённой, успешный повтор не считается её исправлением.

Основание протокола: [официальная схема Chromium](https://chromedevtools.github.io/devtools-protocol/tot/Page/#event-downloadProgress).
Событие experimental/deprecated; не гарантируется каждой версией WebView2.
Факт наличия файла или 100% сам по себе не доказывает завершение проверки браузером.
