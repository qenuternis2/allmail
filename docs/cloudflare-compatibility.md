# Cloudflare Dashboard: совместимость защиты

Проверено 5 октября 2026 на Windows/WebView2 154.0.4258.53 через production
WebView2Engine, на публичной странице https://dash.cloudflare.com/login.
Данные аккаунта не вводились, форма не отправлялась, взаимодействия с challenge
не было. Результат подтверждает состояние анонимной формы, а не вход в аккаунт.

## Наблюдения

| Настройка | Результат |
| --- | --- |
| Отпечаток: настройки среды выполнения; отслеживание: строгое | Форма открыта, Sign in доступна; повторено в двух запусках |
| Максимальная защита отпечатка; отслеживание: строгое | HTTP 403 / Performing security verification |
| Максимальная защита; отслеживание: сбалансированное | Ошибка Turnstile 600010, Sign in отключена |
| Максимальная защита с отдельным исключением таймеров или шрифтов | Ошибка Turnstile 600010, Sign in отключена |
| Максимальная защита со всеми 20 существующими исключениями | Проверочная страница HTTP 403; UA Client Hints остаются ограничены |
| Режим 5, нативные Client Hints, все исключения | Форма открыта, Sign in доступна |
| Режим 6, ограниченные Client Hints, те же исключения | Проверочная страница HTTP 403 |
| Режим 5, нативные Client Hints, блокировки графики/Canvas/Audio/Speech | Ошибка Turnstile 600010, Sign in отключена |

Парное сравнение режимов 5/6 с одинаковыми исключениями показывает отдельную
несовместимость ограничения UA Client Hints. Дополнительный отказ при нативных
Client Hints показывает, что их восстановления недостаточно: остаётся конфликт
с комбинацией блокировок графики, чтения Canvas, Web Audio и синтеза речи.
Вклад отдельных API этой комбинации не изолирован. Ошибка регистрации Service
Worker в максимальном режиме также наблюдалась, но её причинная связь с отказом
Turnstile не установлена. Внешние 403 для анонимных API/аналитики встречаются и
в контрольном режиме и сами по себе не означают, что форма входа сломана.

Воспроизведённое сообщение страницы: `There was a problem with verification.
Please reload and try again.` Кнопка имеет disabled=true после отказа проверки.
Отдельные существующие исключения и смена уровня отслеживания не обеспечили
совместимость максимального режима в этих наблюдениях.

## Проверенный вариант настройки

Для отдельного профиля Cloudflare выбрать «Защита отпечатка → Настройки среды
выполнения» и полностью перезапустить профиль. «Защита от отслеживания → Строгая»
может оставаться включённой. Прокси, часовой пояс и отдельная политика WebRTC
задаются независимо. В этом профиле снимаются ограничения источников отпечатка
выбранного графического режима; это компромисс совместимости и конфиденциальности.

Работа реального входа зависит также от аккаунта, IP/прокси, текущей политики
Cloudflare и возможной интерактивной проверки. Анонимные проверки не гарантируют
успешную авторизацию в пользовательской сети.

## Воспроизводимая диагностика

Workflow `cloudflare-public-compatibility-diagnostics` вручную запускает нативные
профили без пользовательских данных. Фиксируются ошибки, публичные HTTP-статусы,
состояние формы и скриншоты. Значения полей и URL query не записываются.

Первый набор: [Windows-наблюдения](https://github.com/qenuternis2/allmail/actions/runs/37351296693).
Парное сравнение Client Hints: [Windows-наблюдения](https://github.com/qenuternis2/allmail/actions/runs/37352096689).

Cloudflare описывает возможные конфликты fingerprinting/canvas blockers в
[поддержке браузеров](https://developers.cloudflare.com/cloudflare-challenges/reference/supported-browsers/).
`600*` описан как generic challenge failure в
[справке ошибок Turnstile](https://developers.cloudflare.com/turnstile/troubleshooting/client-side-errors/error-codes/).
