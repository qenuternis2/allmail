# Windows 11 ARM / DPI — 7 октября 2026

Все четыре workflow используют `windows-11-arm`: сборка, релиз,
Proton и Cloudflare diagnostics. Перед работой обязательна проверка
`Win32_OperatingSystem.ProductType == 1`, Caption Windows 11 и native ARM64.
Windows Server fallback отсутствует. Значение WindowsProductName на образе
остаётся «Windows 10 Enterprise»; `OsName` и CIM Caption показывают
**Microsoft Windows 11 Enterprise**, build **26200**. Номер ядра `10.0`
сам по себе не определяет маркетинговую версию Windows.

Существующие приложение, self-contained публикации и native harness остаются
**win-x64**. На этом runner они работают через эмуляцию x64 Windows 11.
Установлены pinned x64 .NET SDK **10.0.100** и WebView2 Evergreen
через официальный Microsoft bootstrapper, выбирающий архитектуру устройства.
Пакеты, бизнес-логика и публичные интерфейсы не менялись.
**0.1.54** исправляет обрезание кнопок создания профиля при ограниченной высоте:
поля прокручиваются, footer с действиями остаётся внизу. Исходный прогон ниже
выполнен до этого изменения, на **0.1.53**.

## DPI fixture

[`8f4252c`, run 37632384253](https://github.com/qenuternis2/allmail/actions/runs/37632384253)
прошёл все **40 DPI observations** и per-user installer с пятью операциями.
Обрезание кнопки создания на 200% воспроизведено до исправления в
[`2709a7e`](https://github.com/qenuternis2/allmail/actions/runs/37630672329).
После исправления обе кнопки находятся внутри client content на всех четырёх
масштабах. Footer не уходит вместе с прокручиваемыми полями.

Фактическая матрица виртуального дисплея **1024×768**:

| Масштаб | Метод | GetDpiForWindow | WPF DPI | Покрытие |
| --- | --- | --- | --- | --- |
| 100% | Смена DPI Windows | 96 | 96 | Все окна + live viewport/DPR/session |
| 125% | Смена DPI Windows | 120 | 120 | Все окна + live viewport/DPR/session |
| 150% | Synthetic WM_DPICHANGED | 120 | 144 | WPF layout, viewport/session; OS scale NotPerformed |
| 200% | Synthetic WM_DPICHANGED | 120 | 192 | WPF layout, viewport/session; OS scale NotPerformed |

Драйвер допускает только 100/125%; подходящего режима >=1920×1200 не объявляет.
Полное размещение минимального MainWindow (900×560 DIP) на этом маленьком
рабочем столе при 125% не подтверждается: физическая ширина окна 1125 px
превышает 1024 px дисплея. Проверка bounds относится к действиям внутри окна,
не к отсутствию выхода всего окна за экран. Нужен более крупный дисплей и
отдельная проверка малых рабочих областей/минимального размера оболочки.

Этот же run затем отклонил directory benchmark: **p95 207.69 ms** при пороге
200 ms (outliers в selection, 30 исходных samples сохранены). Это реальный
результат, не успешный полный прогон. Причина задержек не установлена.
DPI block перенесён после reference benchmark и остальных native fixtures,
чтобы изменения глобального display state и большие preview bitmaps не
предшествовали измерению стартовой конфигурации. Порог и число samples
не изменены; это изоляция тестов, не доказательство исправления production
latency. Полный прогон после изменения порядка должен оцениваться отдельно.

[`78248d0`, run 37634156301](https://github.com/qenuternis2/allmail/actions/runs/37634156301)
после переноса DPI получил p95 **103.03 ms** (порог 200 ms сохранён),
прошёл UI/import/credentials/crash/recovery и installer. Затем реальный
background Range resume 6 МиБ не закончил transfer за 20 секунд: native
progress продолжался, но полный payload ещё не был принят. Повтор PR получил
98.01 ms и такой же download timeout. Полными успешными прогонами они не являются.
Fixture теперь искусственно замедляет по 150 ms только rate/pause transfers,
а восстановленный broken.bin отправляет без pacing и измеряет время отправки.
Размер **6 МиБ**, реальный Range, закрытая вкладка, побайтовая проверка и
20-секундный deadline сохранены. Скорость произвольных пользовательских файлов
этим не сертифицируется; production download код не менялся.

## Итоговый полный прогон 0.1.54

[`800b0f7`, run 37636442440](https://github.com/qenuternis2/allmail/actions/runs/37636442440)
и [PR run 37636449874](https://github.com/qenuternis2/allmail/actions/runs/37636449874)
**успешны целиком**, без повторных попыток этих runs: **653 core / 108 JS**,
Core/Experimental self-contained, все native WebView2 fixtures и installer.
**40/40 DPI observations** прошли; client PNG снимаются в точных Win32
client pixel bounds с фоном окна, без повторного применения margin родителя.
Браузер снимается отдельно через CapturePreview.

Directory p95 **118.08 ms** при прежнем 200 ms лимите. Сервер восстановленного
Range отправил оставшиеся **5 898 240 байт за 16 ms**, native download завершился
в прежнем 20-секундном deadline. Полный payload 6 МиБ проверен побайтово после
закрытия исходной вкладки; сохранены одна запись и один save choice.
Crash/recovery, 20 lifecycle cycles, хранилища, вкладки, аппаратные permission
denials, fingerprint restrictions, доверенный fixture TLS и proxy boundaries
также прошли. Runtime **154.0.4258.62**, SDK **1.0.4258.31**.

Локально прошли `build.ps1`, compile native harness, Roslyn analyzers,
workflow YAML и PowerShell syntax. Отдельного frontend typecheck/linter в
проекте нет; C# типы проверяются сборкой с warnings-as-errors, JS — 108 тестами.
Непроверенные физические DPI 150/200, мониторы, минимальный desktop fit,
account sessions и OS-wide DNS/UDP не переводятся в Pass.

Harness получил тот же **PerMonitorV2 manifest**, что production EXE.
`DpiSmoke.cs` показывает настоящие production окна: MainWindow,
создание профиля, все пять вкладок редактора, группы и подтверждение.
Проверяются масштабы **100%, 125%, 150%, 200%**, соответствующий WPF DPI,
размеры кнопок и их границы внутри окон. PNG рендерятся при измеренной
плотности пикселей. Реальный профиль с loopback-страницей остаётся открытым:
проверяются viewport, действие DOM-кнопки и сохранённый LocalStorage marker.
Для браузера сохраняются отдельные WebView2 CapturePreview PNG, поскольку
WPF RenderTargetBitmap не снимает его HWND.

Только на одноразовом runner с одним активным дисплеем fixture пробует сменить
масштаб через driver-specific DisplayConfig packets -3/-4. Это необязательный
недокументированный test probe, не production API. Исходный масштаб
восстанавливается в Dispose. При отказе драйвера реальная смена масштаба
отмечается **NotPerformed**; вместо неё отдельно проверяется доставка
**WM_DPICHANGED** настоящим HWND и реакция WPF. JSON сохраняет mode,
запрошенный процент, HWND DPI, WPF DPI, размеры PNG и CSS/DPR браузера.
Для настоящей смены масштаба обязательны подтверждение GetDpiForWindow
и согласованный browser DPR. Synthetic message не является подтверждением
физической смены масштаба Windows.

Чтобы большие масштабы помещались, fixture может временно выбрать объявленный
драйвером режим от 1920×1200 до 2560×1600 через EnumDisplaySettings и
ChangeDisplaySettings с предварительным CDS_TEST. Это разрешено только одному
активному дисплею одноразового GitHub runner. Неподдерживаемое увеличение
разрешения отмечается NotPerformed; исходное разрешение восстанавливается
после восстановления DPI. Конфигурация пользовательских экранов не меняется.

Скрипт Test-Installer теперь пишет отдельные `installer-operation-N.log`
и сообщения начала/конца операций. `Start-Process -Wait` сохраняет ожидание
всего дерева Inno; один Process.WaitForExit этого не обеспечивает, поскольку
uninstaller запускает временный дочерний EXE. Внешний таймаут шага CI остаётся
5 минут. Эти изменения относятся к тестовому скрипту, не к самому установщику.

Ручной rebuild старого version tag получает ARM setup/runtime helpers из
коммита исполняемого workflow через отдельный checkout. Бинарники продолжают
собираться из запрошенного tag; отсутствие нового helper в историческом tag
не является причиной возврата к Windows Server.

Несколько физических мониторов, перенос между ними, пользовательский mouse
hit-testing, произвольные разрешения, аппаратные драйверы и визуальная оценка
качества шрифтов на физическом дисплее остаются **NotPerformed**.
Переключение browser `--force-device-scale-factor` в остальных тестах проверяет
privacy DPR и не засчитывается как DPI Windows. Исходные сетевые и account
ограничения [приёмки 0.1.53](acceptance-report-0.1.53.md) сохраняются.
