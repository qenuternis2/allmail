## Архитектура и границы изменений

`ProtonProfiles.Core` — платформенно-независимое ядро .NET 10: SQLite, настройки,
жизненный цикл профилей, прокси-посредник, GeoIP, политики защиты и встроенные JS.
`ProtonProfiles.App` — WPF/WebView2 для Windows x64. Core и Experimental Proxy
собираются отдельно; `build.ps1 -Publish` создаёт self-contained публикации.
Тесты ядра и четыре Node.js-набора выполняются локально; нативный стенд WebView2
использует Windows CI и исходники производственного приложения.

Сигнатуры публичных методов, схема SQLite/JSON, папки профилей, политики защиты,
сетевые маршруты и зависимости сохранены. Версия приложения и формат отчёта
не менялись: выпуск нового EXE не входит в этот аудит.

## Что сохранено и что требует отдельной проверки

Подтверждённо лишних зависимостей, исходных файлов и временных файлов в Git не
найдено; ничего из них не удалено. MaxMind используется для поддерживаемого импорта
MMDB, GeoTimeZone — для legacy DAT, SQLite — для хранилища, JsonSchema.Net — для
тестов обмена. Coverlet и тестовые адаптеры загружаются инфраструктурой тестов.
JS/HTML/значки загружаются из embedded/WPF resources; обработчик закрытия окна SDK
находится через reflection в `BrowserWindowCloseHandling.cs`. Отсутствие прямого
вызова этих ресурсов/обработчиков не означает, что они не используются.
Игнорируемые публикации и результаты предыдущих проверок оставлены.

| Приоритет | Файл | Оставшийся вопрос |
| --- | --- | --- |
| P2 | `src/ProtonProfiles.App/Browser/BrowserDownloadIdentity.cs`, `_begun`; `WebView2Session.cs`, `_downloadChoices` | Идентификаторы уже завершённых загрузок и некоторые выборы пути сохраняются до закрытия контроллера. Для долго живущей вкладки это накопление памяти. Перед очисткой нужно проверить поздние CDP/SDK события, отмену диалога и повтор Range-запроса; действующий механизм возобновления не изменён. |
| P2 | `src/ProtonProfiles.Core/Diagnostics/ConnectionLogFile.cs`, конструктор/`Dispose`; `src/ProtonProfiles.App/Browser/WebView2Session.cs`, `CloseAsync` | Ошибка записи заголовка не имеет явного освобождения уже открытого потока; ошибка сброса журнала при закрытии может прервать освобождение контроллеров и посредника. Нужен отдельный тест отказа файловой системы и нативного завершения. Обычные сценарии CI не воспроизводят этот путь. |
| P2 | `src/ProtonProfiles.Core/Lifecycle/ProfileLifecycleService.cs`, `ObserveUnexpectedExit`/`ObserveRecovery` | `ContinueWith(async ...)` создаёт вложенную задачу, которая не наблюдается. Ошибка подписчика `StateChanged` может остаться ненаблюдаемой. Требуется определить обработку таких ошибок и проверить поток UI/блокировку профиля; автоматическое изменение восстановления не внесено. |
| P3 | `scripts/Update-WebView2Runtime.ps1` | Загрузка установщика не повторяется при обрыве HTTP. В предыдущих Windows-прогонах такой обрыв встречался; исходный прогон этого аудита прошёл. Возможное улучшение — ограниченный повтор загрузки с сохранением проверки подписи Microsoft. |
| P3 | `.github/workflows/windows.yml`, `.github/workflows/proxy-release.yml` | CI предупреждает, что actions `@v4` рассчитаны на устаревший Node.js 20 и принудительно запускаются на Node.js 24. Прогоны успешны. Переход на новые major-версии actions требует отдельного согласования; версии не изменены. |

Частичная схожесть классов наблюдения приватности и большой размер WebView2Engine
сами по себе не доказывают ненужность кода. Универсальные обёртки и массовое
форматирование не добавлены. Ручная приёмка интерфейса, физическое аудио, все версии
Evergreen/драйверы и полная сетевая изоляция этими проверками не подтверждаются.
